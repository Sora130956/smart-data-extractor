绿框 = 项目根（定位） 绿底 = Day5 新增模块 第 1 层 = 包职责 第 2 层 = 模块职责 「决策」标签 = 可展开的核心设计
  • smart-data-extractor LLM 驱动的数据提取：非结构化纯文本 → 带置信度评分 + 成本追踪的结构化数据（Upwork portfolio MVP，CLI + FastAPI 双入口）
    • config.py 类型安全配置：pydantic-settings 读取 OPENAI_API_KEY / model / max_concurrency
      • get_settings() lru_cache 单例，自动加载 .env
        决策
        Day1：弃用 os.getenv 裸读，改 pydantic-settings——类型安全 + 单例 + 测试可 cache_clear。
    • validators/ 格式校验最底层：email / phone / url / date 正则与归一化，无效 → None
      • formats.py 纯函数，被 models 的 field_validator 调用
        决策
        置信度三级链：LLM 自评 → validator 置 None → 业务层修正。校验失败时字段为 None、confidence 归 0.0。
    • models/ 纯数据模型，无业务逻辑；每个字段配对 xxx_confidence ∈ [0,1]
      • base.py · ConfidenceBase 统一 model_config + 置信度字段约定
        决策
        Day1：extra=forbid 防拼写错误；validate_assignment 运行时赋值也校验。基类只为统一配置与扩展点，不过度设计。
      • contact.py / invoice.py / lead.py 三个预制场景模型（invoice 含嵌套 line_items）
        决策
        Lead 按 BANT 重构（Day1）：job_title=Authority、budget_range=Budget、timeline=Timeline、notes=Need，符合 CRM 行业标准。
      • dynamic.py · create_dynamic_model() 用户 JSON schema → 运行时 Pydantic 模型
        决策
        Day1：选 create_model() 而非 StructuredDict——类型安全、实例化即验证、与预制模型 API 一致。
    • presets/ 预制场景 = 模型 + prompt 绑定；PRESETS 注册表 + get_preset()
      • base.py · Preset frozen dataclass：name / model_class / prompt_template
        决策
        Day2：模型与 prompt 绑定在同一对象，防「改模型忘改 prompt」；注册表 dict 由 preset.name 派生，key 不漂移。
      • contact.py / invoice.py / lead.py 场景 prompt：缺失 → null，confidence 0.0-1.0 自评
    • extraction/ 核心业务层：Agent 构造、单条/批量提取、成本追踪（API/CLI 的唯一入口）
      • agent.py build_agent 新鲜实例 / get_preset_agent 缓存实例 / 共享限流器
        决策 D-006
        lru_cache 缓存生产 Agent（key = preset+model_ref，天然有界；动态 schema 不缓存防泄漏）；共享 ConcurrencyLimiter 做全局限流（替代手写 Semaphore）；统一 temperature=0 求确定性。
      • extractor.py · extract_data() 单条提取，返回 data + tokens_used + cost_usd
        决策 D-005 / D-006
        model 注入缝：测试传 TestModel 离线跑，生产回落 settings.model，配置读取延迟到真正需要时；成本优先取 usage.cost（框架自动填充），calculate_cost 仅作无价目模型 fallback。
      • batch.py · batch_extract() 批量提取：asyncio.gather 并发 + 聚合；双失败语义（D-008 落定）
        决策 D-007 / D-008
        不手写 Semaphore（Day3）：限流由 agent 层共享 ConcurrencyLimiter 承担；失败语义双模式（Day4）：默认 fail-fast 不变；return_exceptions=True 时失败条变 error 项（data=None、用量归零、error="ExcType: msg"），成功条带 error=None，聚合只计成功——API 层固定选用容错模式。顺带补 instructions 透传（R-5）。
      • cost.py · calculate_cost() genai_prices 封装，Decimal → float（JSON 契约）
        决策
        边界收敛：第三方库的 Decimal 怪癖在封装层消化，不泄漏到 API 响应契约。
    • api/ FastAPI 传输层：DTO 边界校验 + 薄路由 + DI 缝（tests 用 dependency_overrides 注入 fake）
      • schemas.py 请求/响应 DTO：_ExtractionTarget 基类收口 preset XOR schema，响应含 succeeded/failed 计数
        决策 D-008
        校验全部前置到 DTO（model_validator）：both/neither、未知 preset（查 PRESETS）、schema 缺 type 键 → 422；路由保持薄。schema 字段用 alias：字面命名会撞 BaseModel.schema。
      • routes.py /health + /extract + /batch_extract；Depends(get_extract_fn / get_batch_fn) 注入缝
        决策 D-008
        错误分层：请求形状错误 422（DTO），提取层 ValueError 400，其余 500；批量固定 return_exceptions=True——HTTP 契约是部分容错，一条坏数据不拖垮整批。
      • __init__.py · create_app() 装配路由；模块级 app 实例 = uvicorn 目标（smart_data_extractor.api:app）
    • cli.py Typer CLI 入口：extract / batch 两命令（[project.scripts] smart-data-extractor → cli:app）
      • extract / batch 命令 参数接线（--text XOR --input-file、--preset XOR --schema）、JSON 序列化、退出码与流分工
        决策 D-009
        CLI 契约（Day5）：batch 固定容错模式（部分结果仍写出，任一条失败 exit 1）；退出码 0/1/2 分层对应 API 200/400/422；stdout 只放数据 JSON、stderr 放汇总与错误——保证 | jq 管道可用。测试经 monkeypatch 打 cli 模块级 extract_data / batch_extract 依赖缝（14 测试，CliRunner，同 batch 测试 DI 纪律）。
