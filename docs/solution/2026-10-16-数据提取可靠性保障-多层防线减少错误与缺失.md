# 数据提取可靠性保障：多层防线减少错误与缺失

> 问题：smart-data-extractor 通过哪些方式减少数据提取的错误、缺失，如何保证结果的可靠性和准确性？
>
> 结论先行：项目**没有任何单一手段能"保证"准确**，而是用 **7 层防线**把错误和缺失层层拦截——「输入层（OCR）→ 约束层（结构化输出）→ 校验层（格式归一化）→ 置信层（自评 + 归零）→ 溯源层（原文定位）→ 人工复核层 → 韧性层（限流/批量容错）」。核心设计哲学是：**宁可显式留空并标记，也不静默编造；让模型的不确定性变成可见、可过滤、可复核的信号。**

## 1. 输入层：OCR 质量与坐标一致性

提取的上限取决于喂给 LLM 的文本。图片/PDF 先经智谱 GLM-OCR（`layout_parsing`）转成带 bbox 的文本块。

- **EXIF 方向矫正**：手机拍照常带 EXIF 旋转，浏览器展示与 OCR 看到的方向不一致会导致 bbox 整体错位。[`_normalize_image_orientation`](file:///d:/freelancer/workspace/code/smart-data-extractor/src/smart_data_extractor/extraction/ocr.py#L97-L134) 在送 OCR 前统一方向，保证坐标系与前端一致。
- **版面感知文本抽取**：[`_extract_text_blocks`](file:///d:/freelancer/workspace/code/smart-data-extractor/src/smart_data_extractor/extraction/ocr.py#L350-L385) 保留文本/表格块并剥离表格 HTML 标签，避免标签噪声污染 LLM 输入。
- **部分失败可见**：[`_build_result`](file:///d:/freelancer/workspace/code/smart-data-extractor/src/smart_data_extractor/extraction/ocr.py#L388-L437) 把没有任何块的页记入 `pages_failed`，多页 PDF 部分页失败时不会被悄悄吞掉，调用方知道"缺了哪几页"。
- **坐标尺度容错**：[`normalize_boxes`](file:///d:/freelancer/workspace/code/smart-data-extractor/src/smart_data_extractor/extraction/locate.py#L90-L138) 兼容 0–1 / 0–100 / 0–1000 / 像素四种尺度（优先用 `data_info.pages[].width/height` 精确换算），修正反向角点、裁剪越界、丢弃退化框，避免上游返回格式漂移造成高亮错位。
- **失败显式化**：[`_ocr_http_error`](file:///d:/freelancer/workspace/code/smart-data-extractor/src/smart_data_extractor/api/routes.py#L53-L90) 把 OCR 故障映射为结构化错误（503 `ocr_rate_limited` / 502 `ocr_upstream_error` / 503 `ocr_network_error`），而不是返回空文本让下游"成功地提取出空数据"。

> 经验：**"静默返回空"比"报错"更危险**——前者会被当成"文档里本来就没有这个信息"。

## 2. 约束层：结构化输出，从机制上堵住编造与漏字段

### 2.1 运行时生成的 Pydantic 模型

[`create_dynamic_model`](file:///d:/freelancer/workspace/code/smart-data-extractor/src/smart_data_extractor/models/dynamic.py#L44-L107) 根据用户/预设 schema 动态生成输出模型，并作为 pydantic-ai 的 `output_type`，让 LLM 输出必须通过校验：

- **必填 vs 可选**（[L74-L78](file:///d:/freelancer/workspace/code/smart-data-extractor/src/smart_data_extractor/models/dynamic.py#L74-L78)）：必填字段不给默认值，缺失会触发 pydantic-ai 输出校验失败并重试；可选字段默认 `None`，即"没找到就是 null"，不允许编造。
- **字段 description 透传给 LLM**（[L79-L85](file:///d:/freelancer/workspace/code/smart-data-extractor/src/smart_data_extractor/models/dynamic.py#L79-L85)）：description 进入 JSON schema，用来消除字段歧义（例如 "公司" 是客户公司还是我方公司）。内置预设为中英双语描述，按 `lang` 选择，见 [seed.py](file:///d:/freelancer/workspace/code/smart-data-extractor/src/smart_data_extractor/db/seed.py#L47-L76)。
- **每字段配一个 `<field>_confidence`**（[L94-L99](file:///d:/freelancer/workspace/code/smart-data-extractor/src/smart_data_extractor/models/dynamic.py#L94-L99)）：`Field(default=0.0, ge=0.0, le=1.0)`，越界值直接校验失败。
- **挂载格式校验器**（[L87-L92](file:///d:/freelancer/workspace/code/smart-data-extractor/src/smart_data_extractor/models/dynamic.py#L87-L92)），见第 3 节。

### 2.2 `ConfidenceBase` 的严格配置

[`ConfidenceBase.model_config`](file:///d:/freelancer/workspace/code/smart-data-extractor/src/smart_data_extractor/models/base.py#L13-L20)：

- `extra="forbid"`：模型不能夹带 schema 之外的字段（防"多编"）。
- `validate_assignment=True`：后续赋值同样触发校验。

### 2.3 Prompt 规则与 temperature=0

- 基础提示词 [`DYNAMIC_PROMPT`](file:///d:/freelancer/workspace/code/smart-data-extractor/src/smart_data_extractor/extraction/extractor.py#L17-L24) 明确：缺失字段返回 null；每字段给 0–1 置信度（1.0=明确无歧义，0.0=未找到）；邮箱小写、日期 ISO、金额为纯数字。内置预设（联系人 / 发票 / 线索，线索采用 BANT 框架）的提示词见 [seed.py](file:///d:/freelancer/workspace/code/smart-data-extractor/src/smart_data_extractor/db/seed.py#L5-L43)。
- 用户自定义 `instructions` 通过 [`_compose_instructions`](file:///d:/freelancer/workspace/code/smart-data-extractor/src/smart_data_extractor/extraction/extractor.py#L43-L51) **追加在基础规则之后**，调用方无法覆盖"缺失返回 null / 置信度契约"。
- [`build_agent`](file:///d:/freelancer/workspace/code/smart-data-extractor/src/smart_data_extractor/extraction/agent.py#L18-L43) 固定 `temperature=0`（[L41](file:///d:/freelancer/workspace/code/smart-data-extractor/src/smart_data_extractor/extraction/agent.py#L41)），降低同一输入多次提取的随机波动。

### 2.4 Schema 本身的安全

[`_validate_identifier`](file:///d:/freelancer/workspace/code/smart-data-extractor/src/smart_data_extractor/extraction/schema_resolve.py#L86-L101) 要求字段名为 snake_case、非 Python 关键字、不以 `model_` 开头、不以 `_confidence` 结尾、无重复；[`resolve_schema`](file:///d:/freelancer/workspace/code/smart-data-extractor/src/smart_data_extractor/extraction/schema_resolve.py#L115-L205) 在**调用 LLM 之前**就拦截非法 schema，避免浪费一次调用后才发现模型构造失败。[`infer_schema`](file:///d:/freelancer/workspace/code/smart-data-extractor/src/smart_data_extractor/extraction/schema_resolve.py#L208-L270) 自动推断字段时限定 3–12 个，且指令要求"不要臆造文档中没有的字段"（[INFER_INSTRUCTIONS](file:///d:/freelancer/workspace/code/smart-data-extractor/src/smart_data_extractor/extraction/schema_resolve.py#L29-L55)）。

## 4. 置信层：逐字段置信度 + "被置空即归零"

只让模型自评还不够——自评值可能与最终值不一致。[`ConfidenceBase._zero_confidence_for_nulled_fields`](file:///d:/freelancer/workspace/code/smart-data-extractor/src/smart_data_extractor/models/base.py#L22-L42) 保证一条不变式（验收项 AC-3）：

> **任何值为 null 的字段，其置信度强制为 0.0。**

无论是 LLM 本身返回 null，还是第 3 节的校验器把非法值置空，置信度都会被同步归零，杜绝"值是空的，置信度却是 0.95"的矛盾数据。这一不变式让前端可以**仅凭置信度 + 是否为空**做可靠的复核判断。

## 5. 溯源层：把提取值定位回原文

可靠性不仅是"提取对"，还包括"人能快速确认对"。项目在**不增加任何模型调用**的前提下，对提取值做本地匹配（决策 D-028 / D-029）：

- 后端 [`match_field_boxes`](file:///d:/freelancer/workspace/code/smart-data-extractor/src/smart_data_extractor/extraction/locate.py#L154-L178)：将值与 OCR 文本块做归一化子串匹配（去空白、忽略大小写、全角转半角，见 [`_normalize`](file:///d:/freelancer/workspace/code/smart-data-extractor/src/smart_data_extractor/extraction/locate.py#L141-L151)），命中则返回对应 bbox。
- 前端 [`matchFieldBoxes`](file:///d:/freelancer/workspace/code/smart-data-extractor/frontend/src/utils/textHighlight.ts#L123-L147) 与 [`findFieldRanges`](file:///d:/freelancer/workspace/code/smart-data-extractor/frontend/src/utils/textHighlight.ts#L82-L99) 保持与后端语义一致（另外会丢掉金额里的千分位逗号，见 [`foldForMatch`](file:///d:/freelancer/workspace/code/smart-data-extractor/frontend/src/utils/textHighlight.ts#L104-L115)）。
- 复核界面中点击字段即高亮原文位置；**未命中则不画框**，宁缺勿错。

## 6. 人工复核闭环：让不确定性可见、可过滤

自动化永远有长尾错误，项目把"人兜底"做成了一等公民。

### 6.1 置信度分档与逐字段阈值

[confidence.ts](file:///d:/freelancer/workspace/code/smart-data-extractor/frontend/src/utils/confidence.ts#L4-L16) 定义：`CONFIDENCE_HIGH = 0.85`、`CONFIDENCE_LOW = 0.7`、`DEFAULT_MIN_CONFIDENCE = 0.85`。

[`needsReview`](file:///d:/freelancer/workspace/code/smart-data-extractor/frontend/src/utils/confidence.ts#L72-L82) 在以下任一情况为真时要求复核：

1. 平均置信度 < 0.7；
2. 存在"不允许为空"的空字段（[`emptyViolatingFields`](file:///d:/freelancer/workspace/code/smart-data-extractor/frontend/src/utils/confidence.ts#L41-L50)）；
3. 存在字段低于其自身阈值（[`belowThresholdFields`](file:///d:/freelancer/workspace/code/smart-data-extractor/frontend/src/utils/confidence.ts#L56-L67)）。

支持**逐字段 `minConfidence`**（issue #2）与"允许为空"档（minConfidence=0）：例如"备注"允许空，而"邮箱"不允许。因为第 4 节保证空值置信度为 0，空字段只按"是否允许为空"规则判定，不会被误判为"低置信度"。

### 6.2 复核状态机

[review.ts](file:///d:/freelancer/workspace/code/smart-data-extractor/frontend/src/utils/review.ts) 提供：

- [`reviewState`](file:///d:/freelancer/workspace/code/smart-data-extractor/frontend/src/utils/review.ts#L125-L155)：`none / pending / reviewed` 三态；
- [`applyFieldEdit`](file:///d:/freelancer/workspace/code/smart-data-extractor/frontend/src/utils/review.ts#L17-L34)：首次编辑时快照 `originalData`、记录 `reviewedFields`，保留"AI 原值 vs 人工值"对照，可追溯；
- [`problemFields`](file:///d:/freelancer/workspace/code/smart-data-extractor/frontend/src/utils/review.ts#L99-L114)：汇总需关注字段；
- [`nextPendingItem`](file:///d:/freelancer/workspace/code/smart-data-extractor/frontend/src/utils/review.ts#L173-L187)：Ctrl+S 保存后自动跳到下一个待复核条目，把人工精力集中在真正有问题的条目上。

## 7. 韧性层：防止"因调用失败造成的缺失"

很多"数据缺失"并非模型能力问题，而是 429 / 超时 / 单条失败拖垮整批。

- **LLM 全局并发限制**：[`shared_concurrency_limiter`](file:///d:/freelancer/workspace/code/smart-data-extractor/src/smart_data_extractor/extraction/agent.py#L46-L56) 让所有 Agent 共用一个 `ConcurrencyLimiter`；预设 Agent 缓存复用见 [`get_preset_agent`](file:///d:/freelancer/workspace/code/smart-data-extractor/src/smart_data_extractor/extraction/agent.py#L59-L79)。
- **OCR 自适应限流**：[`_RequestPacer`](file:///d:/freelancer/workspace/code/smart-data-extractor/src/smart_data_extractor/extraction/ocr.py#L180-L239)（AIMD：遇 429 间隔翻倍，成功后 ×0.75 衰减，上限 10s）+ [OCR 信号量](file:///d:/freelancer/workspace/code/smart-data-extractor/src/smart_data_extractor/extraction/ocr.py#L242-L251)；重试用指数退避、尊重 `Retry-After` 并加 25% 抖动（[`_backoff_delay`](file:///d:/freelancer/workspace/code/smart-data-extractor/src/smart_data_extractor/extraction/ocr.py#L262-L271)、[`_post_with_retries`](file:///d:/freelancer/workspace/code/smart-data-extractor/src/smart_data_extractor/extraction/ocr.py#L274-L316)）。详细原理见 [大模型API限流治理](./2026-10-15-大模型API限流治理-并发信号量为什么不够与自适应请求节奏.md)。
- **前端自动重试**：[`withOcrAutoRetry`](file:///d:/freelancer/workspace/code/smart-data-extractor/frontend/src/utils/parseRetry.ts#L18-L34) 对限流错误按 8s / 15s / 30s 重试。
- **批量逐条容错**（D-007）：[`batch_extract`](file:///d:/freelancer/workspace/code/smart-data-extractor/src/smart_data_extractor/extraction/batch.py#L19-L89) 与路由层 `return_exceptions=True`（[routes.py](file:///d:/freelancer/workspace/code/smart-data-extractor/src/smart_data_extractor/api/routes.py#L257-L291)）让单条失败只产生 `{"data": None, "error": ...}`，不影响其它条目；统计只计成功项，失败可见、可单独重试。

## 9. 已知局限（必须诚实面对）

| 局限 | 影响 | 方向 |
|------|------|------|
| **置信度是模型自评，未校准** | 0.9 不等于 90% 正确，可能过度自信 | 校准化 + 一致性采样，见 [置信度可靠性](./2026-10-11-置信度可靠性-从模型自评到校准化与一致性采样.md) |
| 无多次采样 / 交叉验证 / logprob | 单次输出的随机错误无法被发现 | 引入 N=3 或 5 的一致性采样，按一致率校正置信度 |
| 溯源匹配只用于 UI 高亮，**不作为准确性闸门** | 值在原文中根本不存在（疑似幻觉）时，系统不会自动降置信 | 将"值是否出现在原文"作为信号，未命中自动降置信 |
| 本地匹配是精确子串匹配 | 值被拆到多个块、OCR 轻微错字时漏匹配 | 增加模糊匹配（编辑距离）、跨块拼接 |
| 邮箱 / URL 正则较基础 | 个别边缘格式误判 | 视需要引入成熟校验库 |
| 日期格式有歧义 | `%m/%d/%Y` 先于 `%d/%m/%Y` 尝试，`03/04/2026` 可能解析反 | 结合语种/地区或让模型输出时标注 |
| 电话归一化丢失 `+` 与国家码 | 国际号码信息损失 | 保留 E.164 格式 |
| 校验器"静默置 None" | 格式错误的原值丢失，人只看到空值 | 保留原始值到备注 / 审计字段，供人对照 |
| `required=True` 依赖 pydantic-ai 校验重试 | 重试耗尽时整条失败 | 配合批量容错，向用户明确提示 |

## 10. 一句话总结

**这个项目的可靠性来自"组合拳"而非单点保证：** 约束输出结构以防编造和漏字段 → 确定性校验清洗脏值 → 置信度（含"空即零"不变式）暴露不确定性 → 溯源高亮降低核对成本 → 逐字段阈值把人工精力导向最可能出错的地方 → 限流与批量容错避免"因调用失败而缺数据"。最大的待补短板是**置信度尚未校准、缺少独立于模型自评的准确性信号**，这也是后续演进的重点。

## 11. Upwork 接单：客户要求"准确、完整、可靠"时的标准方案

> 用途：客户在需求里写了"必须保证提取结果准确 / 完整 / 可靠"时，直接复用本节来写 proposal、沟通范围和报价。

### 11.1 先定调：不承诺"100% 准确"，承诺"可度量 + 可兜底"

LLM 提取不可能做到 100% 正确，对客户承诺绝对准确既不诚实，也会在验收时变成风险。更稳妥、也更专业的说法是：

1. **把"准确"变成可量化的指标**：双方约定评测集和指标（字段级准确率、完整率），达标即验收。
2. **把"不确定"变成可见的信号**：每个字段带置信度，低置信或为空的字段自动进入人工复核队列。
3. **把"出错"变成可追溯、可修正**：保留 AI 原值与人工修改值，错误能回溯、能沉淀为评测样本。

一句话：**不是保证 AI 永远不错，而是保证"错的会被发现，漏的会被标出，最终交付给客户的是经过兜底的数据"。**

### 11.2 三个词分别怎么落地

| 客户要求 | 我的做法 | 对应项目能力（现有） |
|----------|----------|----------------------|
| **准确性** | 结构化输出禁止编造；格式校验与归一化；`temperature=0`；逐字段置信度；溯源高亮便于核对 | 第 2、3、4、5 节 |
| **完整性** | 字段缺失显式为 null 而不是丢掉；空值置信度强制为 0 且按"是否允许为空"判定；OCR 页失败记录 `pages_failed`；批量中单条失败可见、可重试，不吞数据 | 第 1、4、6、7 节 |
| **可靠性** | 限流自适应与重试；批量逐条容错；错误结构化返回；验收测试与离线 `TestModel` 保证回归稳定 | 第 7、8 节 |

### 11.3 交付流程（可直接写进 proposal 的步骤）

1. **需求澄清 + 字段定义**：与客户逐字段确认含义、格式、是否必填、是否允许为空（对应 `description` / `required` / `format` / 逐字段 `minConfidence`）。字段描述写得越清楚，错误越少。
2. **建立黄金评测集**：请客户提供 30–50 份有代表性的样本（含脏数据、模糊扫描、边缘情况），由客户或双方共同标注标准答案。这是"准确率"可被验收的前提。
3. **迭代调优**：在评测集上跑字段级准确率 / 完整率，针对错误类型调 prompt、字段描述、校验规则、OCR 前处理，直到达到约定指标。
4. **置信度分流**：按客户对"错误容忍度"设定阈值——高置信自动通过，低置信 / 空值 / 关键字段进入人工复核界面（带原文高亮定位，核对一眼可见）。
5. **交付与验收**：给出评测报告（总体与逐字段指标、典型失败案例与处理方式），客户在独立样本上抽检验收。
6. **上线后监控**：持续收集人工修改记录（AI 原值 vs 人工值），回流为新评测样本，定期复评。

### 11.4 增强项：一致性采样（规划中，尚未实现）

> 状态说明：**本项目目前尚未实现一致性采样**，现有置信度仍是模型自评。对客户沟通时要如实表述为"可选增强 / 路线图"，不要说成已有能力。

- **做法**：对同一份输入以 `temperature>0` 独立提取 N 次（N=3 或 5），逐字段比较归一化后的值，用**一致率**来校正/替代自评置信度；N 次不一致的字段强制进入人工复核。
- **价值**：自评置信度可能过度自信，而"多次独立结果是否一致"是不依赖模型自述的稳定性信号，更能识别随机性错误，使 0.9 的置信度更接近真实的 90% 正确率。
- **成本**：LLM 调用量约为 N 倍。可只对低置信字段或客户标记的关键字段触发，以控制成本与时延。
- **注意**：当前 Agent 固定 `temperature=0`（见 [agent.py](file:///d:/freelancer/workspace/code/smart-data-extractor/src/smart_data_extractor/extraction/agent.py#L41)），采样模式需要单独配置温度。
- **理论与校准方法**：见 [置信度可靠性：从模型自评到校准化与一致性采样](../重要结论和经验/2026-10-11-置信度可靠性-从模型自评到校准化与一致性采样.md)。

对高要求客户（财务、合规、医疗类数据），建议把"一致性采样 + 置信度校准"作为**可选的第二阶段**单独报价；对一般客户，现有防线加人工复核通常足够。

### 11.5 可直接复用的 Proposal 话术（英文）

> You asked for accurate, complete, and reliable extraction — here is how I deliver that in a *measurable* way rather than just promising it:
>
> 1. **Define "accurate" with you up front.** We agree on the fields and a small gold-standard sample set (30–50 real documents). I report field-level accuracy and completeness against it, and we sign off on a target before delivery.
> 2. **Schema-constrained output.** The model can only return the fields you define, with typed formats (email, phone, date, URL normalized). If a value isn't in the document it returns `null` — it never guesses.
> 3. **Per-field confidence + human review.** Every field carries a confidence score. Low-confidence or empty required fields are automatically routed to a review screen that highlights the exact spot in the source document, so a reviewer can verify in seconds.
> 4. **Nothing silently lost.** Failed pages or failed files are reported explicitly and can be retried individually; one bad file never breaks a batch.
> 5. **Traceable and improvable.** Every manual correction is stored next to the AI's original value, so accuracy keeps improving after launch.
> 6. *(Optional add-on)* **Consistency sampling** — run the extraction several times and flag fields where the results disagree, for even more trustworthy confidence scores on high-stakes data.
>
> I can't honestly promise 100% for any AI system, but I can promise errors are caught and surfaced, and that you get numbers to back the claim.

### 11.6 沟通红线与风险提示

- **不要承诺**："100% 准确""零遗漏""无需人工检查"。改说"达到约定指标 + 有兜底机制"。
- **必须提前确认**：原始文档质量（模糊、手写、倾斜会显著拉低 OCR 上限）、字段口径是否唯一、客户能否提供标注样本、可接受的人工复核比例。
- **范围控制**：评测集规模、指标口径、复核人力（谁来复核）写入合同或里程碑，避免验收时"准确"的定义漂移。
- **局限要事先说明**：日期歧义（`03/04/2026`）、国际电话区号、原文中被拆分到多处的值，需要在字段定义阶段与客户约定规则（见第 9 节）。
- **成本透明**：采样 N 次会使调用成本约乘 N；高并发场景受第三方 API 限流影响，批量处理需预留排队时间（见第 7 节）。
